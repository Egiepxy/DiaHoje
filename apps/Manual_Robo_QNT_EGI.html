2. Posição QNT e limite de risco

Dados informados: 0,474 QNT, preço médio US$ 210,93, custo histórico teórico de aproximadamente US$ 99,98, sem taxas ou movimentações posteriores. A metade matemática é 0,237 QNT.

Esses números são referências e não são conferência automática de saldo. Ordens futuras dependem de quantidade livre, filtros de lote, valor mínimo e condições atuais da Binance. Preço médio não obriga vender para empatar nem justifica comprar mais.

O monitor não coloca stop na corretora. Sem ordens protetivas reais e confirmadas, uma queda forte pode ocorrer durante indisponibilidade de rede ou notificações.

3. Como usar o painel no DiaHoje

  1. Abra Robô QNT Spot no DiaHoje.
  2. Toque em Atualizar análise e confira a data e hora do último candle 4h fechado.
  3. Veja o parecer e os indicadores RSI14, EMA9, EMA21, volume relativo, suporte e resistência recentes.
  4. Use 4h como período principal; 1h confirma, 15m dá contexto e diário/semanal/mensal mostram estrutura.
  5. Se desejar, informe quantidade e preço médio na seção da carteira e toque em Salvar localmente. O dado fica neste navegador, não é sincronizado.
  6. A opção Já vendi uma parcela manualmente muda apenas a interpretação do painel; não prova venda real na corretora.
  7. Use Copiar RelGPT para arquivar uma leitura.

Limitação visual: o gráfico atual usa linhas dos fechamentos e EMAs; não é uma tela de envio de ordens nem uma solução completa de candles, volume e ordens.

Os critérios são heurísticos não calibrados. Eles não comprovam taxa de acerto, não garantem lucros e não substituem avaliação de risco. “O indicador sugere; o candle fechado confirma.”

5. Alertas programados e ntfy

O arquivo .github/workflows/qnt-egi-4h.yml está no repositório privado Egiepxy/Meus_Projetos. O cron é 7 * * * *: uma tentativa no minuto 07 de cada hora UTC; o sinal considera o candle 4h fechado. Há também o botão manual Run workflow.

  1. Instalar Python no ambiente do GitHub e executar os testes.
  2. Consultar API pública Binance QNTUSDT 4h e 1h.
  3. Verificar cache para não repetir o mesmo candle.
  4. Publicar parecer QNT no tópico privado definido no workflow do repositório privado. O secret opcional QNT_NTFY_TOPIC pode substituir essa configuração.
  5. Registrar marcador de envio quando o ntfy aceita a mensagem.

GitHub Actions pode atrasar ou descartar agendamentos. Uma execução verde não garante que o Android exibiu a notificação. O monitor é separado do executor local; nenhum deles coloca stop por esse processo.

6. Procedimento para execução vermelha

  1. Acesse Robô QNT EGI no GitHub Actions e abra a execução vermelha.
  2. Abra o job monitor e expanda o primeiro passo vermelho.
  3. Leia o fim do log, identificando o erro exato. Não compartilhe chaves nem tokens.
  4. O erro exibido no print foi 'latin-1' codec can't encode character '\u2022'. O cabeçalho Title foi atualizado para ASCII e os testes agora validam a codificação. Clique em Run workflow para uma nova execução de main; não use Re-run jobs na execução antiga, que pode repetir o código com erro.
  5. Se faltar NTFY_TOPIC, confira o nome do secret sem divulgar seu valor.
  6. Rode Run workflow novamente e registre a hora, o passo e a mensagem de erro ou sucesso.

7. Segredos e proteção de conta

Não coloque API key, API secret, token, senha, arquivo .env ou chaves de recuperação em HTML, no GitHub público, em prints ou neste chat.

O alerta QNT usa um tópico configurado no workflow privado; um secret opcional QNT_NTFY_TOPIC pode substituí-lo. No aplicativo Android ntfy, inscreva-se no tópico combinado com o operador e permita notificações. Um tópico sem autenticação não é um cofre seguro: não inclua saldo, dados de API, documentos ou informações sigilosas nos alertas. Caso o repositório se torne público, migre a configuração para um secret e, preferencialmente, use serviço com autenticação.

Uma futura chave de negociação Binance deve ter apenas o escopo realmente necessário, saques desabilitados, restrição de IP quando aplicável e monitoramento de permissões. O frontend público nunca recebe a chave.

8. Executor local: instalação e limites

O arquivo Robo_QNT_EGI_V1_Spot.zip contém servidor Python separado, painel, testes e configurações. Para leitura no Windows 11: instale Python 3.10+, descompacte, execute iniciar_windows.bat e acesse http://127.0.0.1:8765.

No modo inicial do exemplo: LIVE_TRADING_ALLOWED=0, ALLOW_REBUY=0 e MAX_REBUY_USDT=0. Assim, não está autorizada nenhuma ordem.

Servidor para execução real exigiria hospedagem privada estável, HTTPS, autenticação, persistência do estado de ordens, reconciliação com corretora após timeout e um botão de emergência. GitHub Pages, sozinho, não roda o servidor Python.

9. Checklist obrigatório antes de qualquer ordem real

  • ☑ Execução GitHub manual #2 verde e causa do vermelho registrada (28/10/2026).
  • ☐ Alertas recebidos em pelo menos três candles 4h distintos, sem duplicação inesperada.
  • ☐ Falhas de Binance, ntfy e internet simuladas; nenhuma ordem enviada na incerteza.
  • ☐ Estratégia avaliada em histórico e paper trade; falsos sinais documentados.
  • ☐ Saldo, mínimo negociável e precisão de QNTUSDT verificados.
  • ☐ Regras de tamanho máximo, spread, orçamento de recompra, perdas e desarme testadas.
  • ☐ Segredos somente no servidor privado; nenhuma permissão de saque.
  • ☐ Condição emocional adequada: calma, foco, sem pressa ou vingança.
  • ☐ Autorização explícita, específica e posterior à validação.

Marcar esta lista no papel não libera o robô. A habilitação de execução real dependeria de integração e testes adicionais, ainda não concluídos.

12. Auditoria automática de alertas QNT 4h

O monitor registra uma auditoria para cada execução que consegue analisar o candle, sem enviar ordens ou copiar credenciais. O workflow foi atualizado para gerar um resumo na execução e um arquivo ZIP de evidências disponibilizado pelo GitHub Actions, contendo snapshot.json (dados públicos e parecer) e audit.json (identidade do candle, origem da execução e resultado técnico do envio). A retenção dos artefatos foi configurada para 14 dias.

  1. Abra Robô QNT EGI — GitHub Actions e escolha uma execução.
  2. Na aba Summary, procure Auditoria QNT EGI e confira a origem schedule (automática) ou workflow_dispatch (manual).
  3. Confira a hora do candle 4h fechado, o parecer e o estado do POST no ntfy. Não confunda a hora da execução com a hora do candle.
  4. Em Artifacts, baixe qnt-egi-auditoria-..., quando disponível, para arquivar o JSON antes dos 14 dias.
  5. Para aprovar a próxima fase, documente três candles 4h distintos recebidos por execução agendada e sem alertas duplicados.
Status no arquivo de auditoriaInterpretação
POST_NTFY_ACEITO_MARCADOR_SALVOO ntfy aceitou o POST e o GitHub registrou a marca; não comprova notificação vista no Android.
JA_NOTIFICADO_PELO_CACHEJá existe marcador de envio para o mesmo candle; não enviar outra mensagem.
POST_NTFY_ACEITO_MARCADOR_NAO_CONFIRMADOO POST foi aceito, mas a gravação do marcador não foi confirmada: atenção a possível duplicação.
FALHA_NO_ENVIO_NTFYFalhou a tentativa de publicação; conferir log e não presumir alerta enviado.

Limite importante: a auditoria documenta tentativas realizadas, mas não prova que todos os horários futuros rodaram. Se o GitHub deixar de iniciar uma execução, não haverá artefato dela. O monitor não é uma ordem stop real nem mecanismo de proteção garantida.

13. Simulador QNT EGI V1 — sem dinheiro real

Abra o Simulador QNT EGI no DiaHoje para estudar o comportamento de uma posição fictícia de 100 USDT. O simulador não pede chaves e não acessa saldo. Usa apenas candles públicos 4h/1h fechados e compara a estratégia de vender metade/recomprar com HOLD.

  1. Clique em Executar simulação após verificar taxa e slippage hipotéticos.
  2. Leia patrimônio, HOLD, vantagem, drawdown e registros de operações fictícias.
  3. Se aparecer um sinal pendente no último candle, não interprete como operação executada: o sistema exigirá uma abertura histórica posterior.
  4. Copie o RelGPT ou exporte o JSON para revisão e auditoria; os resumos recentes ficam apenas no navegador local.

A estratégia só executa hipóteses na abertura do candle 4h seguinte ao sinal fechado e exige venda hipotética anterior para recompra. Taxas e slippage são estimativas. Backtest passado não demonstra capacidade preditiva nem valida operações reais, ordens stop ou execução em mercado.

Documentação técnica detalhada no GitHub privado.

11. Glossário, fontes e controle de versão

Spot: mercado à vista. Candle fechado: período concluído. EMA9/21: médias móveis exponenciais. RSI14: indicador de força. VR: volume relativo à média recente; 1,2× representa 20% acima da referência. Slippage: diferença entre preço esperado e executado. Paper trade: simulação sem dinheiro real.
